<p class="docs-lead">
    One binary, every editor. `kotoshu-lsp`
    wraps the gem's `Kotoshu.check` and speaks
    the Language Server Protocol over stdio.
  </p>

  
## Install

  
```text
gem install kotoshu-lsp
```

  
Requires the `kotoshu` gem, installed
automatically as a dependency. Set up at least one language first —
`kotoshu setup en` — the server never
downloads on its own.

  
## Neovim

  
```text
-- built-in LSP, lspconfig entry pending upstream
vim.lsp.start({
name = 'kotoshu',
cmd = { 'kotoshu-lsp' },
filetypes = { 'text', 'markdown', 'asciidoc' },
})

-- or, once lspconfig gains an entry:
require('lspconfig').kotoshu.setup({
cmd = { 'kotoshu-lsp' },
filetypes = { 'text', 'markdown', 'asciidoc' },
})
```

  
## Emacs

  
```text
;; eglot
(add-to-list 'eglot-server-programs
'((text-mode markdown-mode) . ("kotoshu-lsp")))

;; lsp-mode
(lsp-register-client
(make-lsp-client :new-connection (lsp-stdio-connection '("kotoshu-lsp"))
:activation-fn (lsp-activate-on "plaintext" "markdown")
:server-id 'kotoshu))
```

  
## VS Code

  
A packaged extension is on the roadmap; until then wire the binary manually through the
languageServerExample boilerplate — `command: "kotoshu-lsp"`,
languages plaintext and markdown.

Configuration is environment-based:
`KOTOSHU_LSP_LOG` (a log path),
`KOTOSHU_LSP_LOG_LEVEL`
(debug/info/warn/error), and `KOTOSHU_OFFLINE`
to pin the server to cached dictionaries.
