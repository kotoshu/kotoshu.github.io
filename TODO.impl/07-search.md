# 07 — Site Search

## Goal

A Cmd+K fuzzy search over every page, project, audience, and language
group — client-side, dependency-light, working in dev and production.

## Approach

MiniSearch (≈7 kB gz) against a JSON endpoint generated by Astro at
build time from the same data registries that drive the pages. No
post-build crawler (Pagefind) so `astro dev` search works too.

## Tasks

1. `src/data/search.ts` — builds the index entries from
   `site/projects/audiences/languages` registries: `{id, url, title,
   section, description, keywords}`. One entry per page, per project,
   per audience, per language group, plus quick external links.
2. `src/pages/api/search-index.json.ts` — GET endpoint returning
   `{entries}` (statically rendered to `/api/search-index.json`).
3. `src/components/search/SearchModal.vue` — Vue island mounted
   `client:load` in BaseLayout:
   - Opens on ⌘K / Ctrl+K, the header search button (custom event
     `kotoshu:search-open`), and `/` when not typing.
   - MiniSearch config: fields `title^3, section^2, description,
     keywords`; `fuzzy: 0.2, prefix: true`.
   - Keyboard: ↑/↓ navigate, Enter go, Esc close. Backdrop click
     closes. Focus trap on the input.
   - Results grouped with section badges; empty state with quick
     links; loading state while the index fetches (lazy, first open).
4. Header search button with `⌘K` hint affordance.

## Acceptance

- ⌘K opens the modal on any page; typing "lsp" finds kotoshu-lsp;
  "german" or "de" finds the German language entry; Enter navigates.
- Index loads once per session, cached in-module.
- Modal is keyboard-navigable and screen-reader labelled
  (`role="dialog"`, `aria-modal`, labelled input).
